# 04 — Data Model (PostgreSQL)

## 1. ძირითადი წესები

| წესი | მნიშვნელობა |
|---|---|
| Primary key | `uuid` |
| სახელები | `snake_case` (ბაზაშიც და API-შიც) |
| დრო | `timestamptz`, UTC |
| თანხა | მთელი რიცხვი, **თეთრებში** (`*_minor`). ვალუტა `GEL` |
| ენები | თარგმნადი ტექსტი (სახელი, აღწერა, SEO) ინახება `*_translations` ცხრილებში, `ka` / `en` |
| წაშლა | პროდუქტი არ იშლება, გადადის `ARCHIVED` სტატუსში, რადგან ძველ შეკვეთებს სჭირდება |
| Snapshot | შეკვეთა ინახავს პროდუქტის სახელს, ფასს და მისამართს შეკვეთის მომენტის მდგომარეობით. შემდგომი ცვლილებები ძველ შეკვეთებზე არ აისახება |

## 3. ცხრილები

### კატალოგი

- **`categories`**: კატეგორიების ხე (მაგ. „კაბელები“ → „Type 2 კაბელები“).
- **`products`**: SKU, ფასი (დღგ-ის ჩათვლით), სტატუსი (`DRAFT` / `ACTIVE` / `ARCHIVED`), ქარხნული (OEM) ნომრები ძებნისთვის. ტექნიკური მახასიათებლები (ძაბვა, დენი, კონექტორი) ინახება ერთ JSONB ველში, რადგან სხვადასხვა ნაწილს სხვადასხვა მახასიათებელი აქვს.
- **`product_images`**: პროდუქტის სურათები S3-ში, თანმიმდევრობით.

### თავსებადობა

- **`charger_brands`** და **`charger_models`**: დამტენების ბრენდები და მოდელები.
- **`product_compatibility`**: კავშირი პროდუქტსა და დამტენის მოდელს შორის (რომელ მოდელს ერგება ნაწილი).
- უნივერსალური ნაწილი, რომელიც ყველა მოდელს ერგება, მოინიშნება ერთი ველით და კავშირებს არ საჭიროებს.

### მარაგი (ერთი საწყობი)

- **`inventory_items`**: თითოეულ პროდუქტზე ორი რიცხვი: საწყობში არსებული (`on_hand`) და გადაუხდელი შეკვეთებით დაკავებული (`reserved`). ხელმისაწვდომია `on_hand - reserved`.
- **`stock_movements`**: მარაგის ყველა ცვლილების ისტორია (მიღება, გაყიდვა, დაბრუნება, კორექცია). ჩანაწერები მხოლოდ ემატება და არ იცვლება.
- **`stock_reservations`**: checkout-ისას დაკავებული რაოდენობა, ვადით (15 წუთი).

### მომხმარებლები და კალათა

- **`customers`**: მომხმარებელი, რომელიც Identity-ს `sub`-ით არის დაკავშირებული. B2B-სთვის მოგვიანებით დაემატება კომპანიის პროფილი.
- **`addresses`**: მიწოდების მისამართები.
- **`carts`** და **`cart_items`**: კალათა login-ით ან მის გარეშე. ფასი კალათაში არ ინახება, ყოველთვის პროდუქტიდან იკითხება.

### შეკვეთები, გადახდა და ჩეკები

- **`orders`** და **`order_items`**: შეკვეთა, ჯამები და პროდუქტების snapshot.
- **`order_status_history`**: სტატუსის ყოველი ცვლილება: ვინ, როდის, საიდან სადამდე.
- **`payments`** და **`refunds`**: Billing-ის გადახდები და დაბრუნებები.
- **`fiscal_receipts`**: გაყიდვისა და დაბრუნების ჩეკები და მათი სტატუსი.

### ტექნიკური ცხრილები

| ცხრილი | რისთვის |
|---|---|
| `outbox_events` | NATS-ში გასაგზავნი ივენთები ([Outbox pattern](02-architecture.md#5-outbox-pattern)) |
| `processed_events` | უკვე დამუშავებული ივენთები, რომ ერთი ივენთი ორჯერ არ დამუშავდეს |
| `failed_events` | ივენთები, რომლებიც რამდენიმე მცდელობის შემდეგაც ვერ დამუშავდა |
| `idempotency_keys` | checkout-ის განმეორებითი request-ის ამოცნობა |
| `admin_audit_log` | ადმინის ყველა ცვლილება |

## 4. მნიშვნელოვანი ლოგიკა

- **თავსებადობის ფილტრი:** მომხმარებლის მიერ არჩეულ მოდელზე ჩანს აქტიური პროდუქტები, რომლებსაც ამ მოდელთან კავშირი აქვთ, და ყველა უნივერსალური ნაწილი.
- **ძებნა:** ქართულად და ინგლისურად, Postgres-ის full-text search-ით; შეცდომით აკრეფილი სიტყვებისთვის `pg_trgm`; ასევე SKU-ით და OEM ნომრით.
- **მარაგის რეზერვაცია:** რაოდენობა იზრდება ერთი `UPDATE`-ით, მხოლოდ იმ პირობით, რომ ხელმისაწვდომი მარაგი საკმარისია. ასე ორი ერთდროული checkout ერთსა და იმავე ბოლო ერთეულს ვერ დაიკავებს. თუ მარაგი არ არის, მთელი checkout ტრანზაქცია უქმდება.
