# 08 — Admin Panel (Next.js)

## 1. ზოგადი
- ცალკე Next.js აპი, ცალკე domain (`admin.<domain>`), SEO არ სჭირდება (`noindex`)
- Auth: იგივე Identity, client `icomers-admin`. შესვლა შესაძლებელია მხოლოდ ადმინის როლით, სხვა შემთხვევაში ნაჩვენებია 403 გვერდი
- UI: **shadcn/ui** + Tailwind, **TanStack Table** (სორტირება, ფილტრები, server-side pagination), **TanStack Query** (cache, mutations, optimistic updates)
- ფორმები: react-hook-form + zod
- ენა: ძირითადად ქართული (en მოგვიანებით, საჭიროების შემთხვევაში)
- Live: `EventSource("/api/admin/events")`. Next.js (BFF) მას Shop API-ის `/admin/events/stream`-ზე გადაამისამართებს. წესები: [SSE](02-architecture.md#6-sse-live-განახლებები)

## 2. მოდულები

### 2.1 Dashboard
- დღევანდელი / კვირის / თვის მონაცემები: გაყიდვები (₾), შეკვეთების რაოდენობა, საშუალო კალათა
- **Live feed (SSE):** ახალი შეკვეთები და გადახდები. ახალი გადახდილი შეკვეთისას — ხმოვანი/ვიზუალური შეტყობინება
- გაფრთხილებები: დაბალი მარაგი, ჩავარდნილი ფისკალური ჩეკები, `needs_attention` შეკვეთები
- ყველაზე გაყიდვადი პროდუქტები

### 2.2 შეკვეთები
- სია: ფილტრები (სტატუსი, თარიღი, მიღების მეთოდი), ძებნა (ნომერი, ტელეფონი, სახელი)
- Live განახლება: ახალი შეკვეთა სიაში ავტომატურად ჩნდება
- დეტალები: ხაზები, ჯამი, კონტაქტი, მისამართი, გადახდის სტატუსი, ჩეკის სტატუსი, სტატუსის timeline
- ქმედებები: სტატუსის შეცვლა (მხოლოდ დასაშვები გადასვლები ჩანს), გაუქმება, refund, შიდა შენიშვნა, ბეჭდვა (picking list / ქვითარი)

### 2.3 პროდუქტები
- სია: სურათი, SKU, სახელი, ფასი, მარაგი, სტატუსი; bulk ქმედებები (გააქტიურება, დაარქივება)
- რედაქტორი ტაბებით:
  - **ძირითადი:** SKU, slug, კატეგორია, ფასი, ძველი ფასი, სტატუსი, featured
  - **კონტენტი:** სახელი და აღწერა **ka / en** გვერდიგვერდ; SEO ველები
  - **სურათები:** drag & drop ატვირთვა (presigned S3), რიგის შეცვლა, alt ტექსტი
  - **მახასიათებლები:** დინამიური ატრიბუტები
  - **თავსებადობა:** ბრენდი → მოდელების multi-select, „უნივერსალური“ checkbox, შენიშვნა მოდელზე
  - **მარაგი:** მიმდინარე რაოდენობა + მოძრაობების ისტორია
- Import/Export: CSV/XLSX (კატალოგის საწყისი შევსებისთვის ძალიან საჭიროა)

### 2.4 კატეგორიები
- ხის რედაქტორი (რიგის შეცვლა drag & drop-ით), თარგმანები

### 2.5 თავსებადობა (დამტენები)
- ბრენდები და მოდელები: CRUD, სურათები
- **მოდელის გვერდი:** ყველა თავსებადი პროდუქტი + „დაამატე პროდუქტები“ ძებნით (bulk მიბმა)
- **მატრიცის ხედი** (სურვილისამებრ): პროდუქტები × მოდელები, checkbox-ებით

### 2.6 მარაგი
- სია: ხელმისაწვდომი / დაკავებული / სულ, დაბალი მარაგის ფილტრი
- ქმედებები: **შემოსვლა** (RECEIPT), **კორექტირება** (ADJUSTMENT, მიზეზი სავალდებულოა), **დაზიანება** (DAMAGE)
- ისტორია: ვინ, როდის, რამდენი, რატომ

### 2.7 მომხმარებლები
- სია, ძებნა, შეკვეთების ისტორია, მისამართები
- რედაქტირება შეზღუდულია: ძირითადი მონაცემები Identity-შია

### 2.8 სისტემა (მხოლოდ admin)
- Audit log: ფილტრები ადმინის, ობიექტისა და თარიღის მიხედვით
- Failed events: სია + „თავიდან გაგზავნა“
- პარამეტრები: გატანის მისამართი და საათები, მიწოდების ფასი, რეზერვაციის TTL, low-stock ზღვარი

## 3. როლები და უფლებები

| ქმედება | admin | manager | content_editor | warehouse |
|---|:-:|:-:|:-:|:-:|
| Dashboard | ✅ | ✅ | ✅ | ✅ |
| შეკვეთების ნახვა | ✅ | ✅ | ❌ | ✅ |
| სტატუსის შეცვლა | ✅ | ✅ | ❌ | ✅ (PROCESSING → READY / SHIPPED) |
| გაუქმება | ✅ | ✅ | ❌ | ❌ |
| Refund | ✅ | ❌ | ❌ | ❌ |
| პროდუქტები / კატეგორიები / თავსებადობა | ✅ | 👁 | ✅ | 👁 |
| ფასის შეცვლა | ✅ | ✅ | ✅ | ❌ |
| მარაგის მოძრაობა | ✅ | ❌ | ❌ | ✅ |
| მომხმარებლები | ✅ | ✅ | ❌ | ❌ |
| Import | ✅ | ❌ | ❌ | ❌ |
| Audit log, სისტემა, პარამეტრები | ✅ | ❌ | ❌ | ❌ |

👁 = მხოლოდ ნახვა

- როლები მოდის Identity-ის ტოკენის `roles` claim-იდან.
- **შემოწმება ხდება Nest-ში** (`@Roles()` + `RolesGuard`). Admin UI ღილაკებს მხოლოდ მალავს — ეს უსაფრთხოების მექანიზმი არ არის.
- ყოველი ქმედება, რომელიც მონაცემებს ცვლის, → `admin_audit_log` (Nest interceptor-ით ავტომატურად).
